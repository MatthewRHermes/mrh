# Experimental LAS-LUSCC

This package implements linearized unitary coupled cluster in a LASSI model
space. It accepts either a LAS reference or a post-kernel LASSI reference and
constructs selected product states for the standard LASSI solver.

```python
from mrh.exploratory.luscc import LUSCC, get_grad_exact

gradients, selected, a_idxs, i_idxs = get_grad_exact(las)
energy, si = LUSCC(las, a_idxs, i_idxs).kernel()
```

Spin targeting is opt-in and uses the physical spin quantum number `S`:

```python
energy, coefficients, s2, residual = LUSCC(
    las, a_idxs, i_idxs, target_spin=0
).kernel()
```

LUSCC fragment vectors need not be spin pure. Consequently this path does not
use the LASSI Clebsch--Gordan basis. It applies fragment `S^2`, `S+`, and `S-`
operators directly to each fragment CI vector and factorizes overlaps of the
resulting product-state terms. The numerical null space of the residual Gram
matrix `<Q psi_i|Q psi_j>`, rather than a compressed `S^2` matrix, defines the
exact target-spin subspace. The constrained Hamiltonian is then solved by the
LASSI projected Davidson engine.

The exact-spin solver builds the dense overlap directly from LASSI's cached
fragment intermediates. It caches local spin images and overlap tables,
groups residual terms by electron sector, and contracts them in tiles. This
retains the physical residual Gram matrix without constructing global FCI
vectors or a dense matrix over all residual terms. Local dot products and
bra-term/ket-term summation order match the original implementation, avoiding
roundoff-driven rotations of the degenerate spin null space. The metric and
spin null space tolerances are unchanged.

As in ordinary LASSI, in-memory H/S2/overlap assembly is used when the estimated
memory fits `max_memory`. The estimate reserves eight raw-state matrices for
operators, spin constraints, and diagonalization work; it is not a hard bound
on peak memory. This avoids rebuilding operator actions during every Davidson
iteration. Set `operator_mode='matrix_free'` to force the contraction path,
which is also used automatically when the estimate exceeds available memory.
Both paths still need dense overlap and spin-residual matrices. The chosen
path is recorded in `solver.exact_spin_operator_mode`.

The projected Davidson preconditioner retains the exact projected Hamiltonian
diagonal. `solver.timings` records wall seconds for preparation, integrals,
operators, overlap, residual, spin basis, projected Davidson, and total. With
in-memory assembly, overlap construction is included in the operators stage.

Spectator factors and repeated local excitation images are shared by default.
Prepared CI arrays should be treated as immutable. Set
`share_spectator_ci=False` to retain independent copies for generated states.
Caches are scoped to one preparation or residual build, so modifying the
reference between calls does not leave stale cached results.

`examples/lasluscc/benchmark_exact_spin.py` records per-stage timings, matrices,
energies, spin expectations, residual norms, and a cProfile report in a new
output directory. `--compare OLD_DIRECTORY` reloads the exact saved reference
and integrals, avoiding phase and degeneracy differences between reference
solves. It asserts matrix, energy, and spin agreement. Use `--no-profile` for
timings without profiler overhead. The Fe4 option uses checkpoint orbitals,
110 M=0 products of the local spin multiplets, and explicitly recorded fixed
single-excitation generators; these are not a gradient-ranked selection.

Excitation indices are generated by the existing LAS-UCCSD operator builder.

### CPU operator-assembly cache

Dense exact-spin operator assembly now defaults to `operator_backend='cached'`:

```python
solver = LUSCC(reference, a_idxs, i_idxs, target_spin=0,
               operator_backend='cached')
solver.kernel()
```

The assembly-local `CachedHamS2Ovlp` subclass caches state-address arrays and
fermionic shuffle signs. Rootspace pairs with one local state per fragment
use scalar spectator overlaps; multi-local-state pairs retain the original
block-overlap routine. Hamiltonian terms, screening thresholds and spin
projection tolerances are unchanged. Caches are recreated for each assembly.
Set `operator_backend='original'` to compare against the previous dense path.
`operator_mode='matrix_free'` still uses the existing contraction path.

The Fe4 study measured 2.45–2.61x faster operator assembly on its tested
spaces, with identical H, S2 and overlap matrices. These are assembly timings,
not a claim of that speedup for the full solve or arbitrary systems. This
integration contains CPU optimizations only and requires no CuPy dependency.
